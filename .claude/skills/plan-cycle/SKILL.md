# 기획 사이클

목표: "지금 만드는 것이 한국 회사 다니는 베트남 직장인에게 정말 도움이 되는가"를 증거로 점검하고, 다음에 할 일을 작게 정한다.

## 1. 읽기
- docs/PRD.md (특히 3장 원칙, 7장 지표, 8장 범위, 9장 가설)
- docs/PLAN_LOG.md 최근 3개 기록
- BACKLOG.md
- NIGHT_LOG.md 최근 기록
- feedback/ 중 마지막 PLAN_LOG 기록 이후에 새로 생긴 파일

## 2. 실제 사용 지표 계산
feedback 파일의 앱 리포트와 DATA(JSON)로 다음을 구하고, PRD 7장 목표와 나란히 적는다.
- 사용한 날 수 (최근 7일)
- 퀴즈 정답률, 복습 정답률
- 세션 평가 분포 (지루함 / 보통 / 유익함)
- 많이 틀린 단어, "이미 앎"으로 넘긴 단어 비율
- 테스터가 직접 한 말 (그대로 인용)

새 피드백이 없으면 "새 증거 없음"이라고 적는다. 이때는 방향을 바꾸지 않는다.

## 3. 가상 사용자 리뷰
learner-critic 서브에이전트에게 현재 dev 버전을 평가하게 한다. 결과는 가상 사용자의 의견이므로 실제 사용 기록보다 약한 근거로 다룬다.

## 4. 진단
- 지금 사용자가 그만둘 가장 큰 이유 1~3개를 증거와 함께 적는다.
- 지난 사이클의 실험(PLAN_LOG의 "효과 확인 대기")이 효과가 있었는지 판정한다: 효과 있음 / 없음 / 아직 모름.
- PRD 9장 가설 중 새 증거로 바뀐 것이 있으면 적는다.

## 5. 가설과 실험
문제마다 한 줄로 적는다: "~하면 ~가 좋아질 것이다. ~로 확인한다."
각 실험이 PRD 원칙(3장)과 "하지 않을 것"(8장)에 맞는지 확인한다.

## 6. BACKLOG.md 갱신 규칙
- **밤 작업**: Sonnet이 1~2시간 안에 끝낼 수 있는 작은 항목만, 최대 5개. 형식은 다음과 같다.
  `- [ ] 무엇 — 왜: (사용자 문제) / 근거: (파일·지표) / 완료 기준: (npm test나 화면에서 확인 가능한 것)`
- **제안**: 다음 항목은 여기에만 적고 "Max 승인 필요"를 붙인다.
  - 큰 변경
  - PRD 원칙이나 범위의 변경
  - 새 외부 서비스
  - 개인정보 관련
  - 콘텐츠 대량 추가
  - 디자인 변경
- **효과 확인 대기**: 끝낸 실험은 다음 피드백에서 확인할 지표와 함께 남긴다.
- 새 증거가 없으면 새 기능 대신 버그, 테스트, 접근성, 콘텐츠 검수 준비 같은 품질 작업만 넣는다.

## 7. 기록
docs/PLAN_LOG.md 맨 위에 다음 형식으로 추가한다.
```
## YYYY-MM-DD 기획 사이클
- 새 증거: ...
- 지표 vs 목표: ...
- 그만둘 이유 Top 3: ...
- 지난 실험 결과: ...
- 이번 실험(가설 → 확인 방법): ...
- Max에게 묻고 싶은 것: ...
```
개인 이름, 회사 이름, 연락처는 쓰지 않는다. 공개 저장소다.

## 8. 커밋
dev 브랜치에 "기획: (한 줄 요약)"으로 커밋하고 푸시한다. main은 건드리지 않는다.
